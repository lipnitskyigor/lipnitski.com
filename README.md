# lipnitski.com — заглушка портфолио

Одностраничник на чистом HTML + CSS. Без сборки: что лежит в репозитории, то и отдаётся.
Только светлая тема — системная тёмная на страницу не влияет.

## Файлы

| Файл | Что это |
| --- | --- |
| `index.html` | Страница |
| `styles.css` | Все стили; цвета, шрифт, интервалы и зерно — переменные на `:root` |
| `cv.pdf` | CV. **Положить в корень самому** — в репозитории его пока нет |
| `cv/index.html` | Редирект `/cv` → `/cv.pdf` (meta refresh + JS + видимая ссылка) |
| `favicon.svg` | Инициал «I» |
| `og-image.png` | Картинка для превью ссылки, 1200×630 |
| `og-image.html` | Исходник `og-image.png` (на сайте не используется) |
| `CNAME` | Домен для GitHub Pages |
| `.nojekyll` | Отключает обработку Jekyll |

## Перед запуском

- Положить `cv.pdf` в корень.

Имя, домен и текст зашиты в `og-image.png`: если контент страницы меняется, картинку нужно перерендерить (см. ниже).

## Локальный просмотр

```bash
python3 -m http.server 8766
```

Открыть <http://localhost:8766>. Через `file://` страница тоже откроется, но ссылки `/cv.pdf` и `/cv` работают только с сервера.

## Настройки в `styles.css`

### Шрифт

В `index.html` запрошены три семейства, браузер скачивает только то, что указано в `--font`. Переключение — одна строка:

```css
--font: "IBM Plex Mono", …;      /* по умолчанию */
/* --font: "Space Mono", …; */
/* --font: "DM Mono", …; */
```

Когда выбор сделан, лишние семейства стоит убрать из `<link>` в `index.html` и `og-image.html`.

### Бумажное зерно

По умолчанию выключено.

```css
--grain: 0;   /* выключено — ровная заливка фона */
```

```css
--grain: 1;   /* включено — тонкий шум feTurbulence поверх фона */
```

Шум наложен маской на цвет текста, поэтому третьего цвета не появляется.
Интенсивность — `--grain-strength` (по умолчанию `0.08`).

### Остальное

- `--gap` — интервал между тремя группами, в строках (сейчас 4).
- `--pad` — отступы от краёв экрана.
- `--top` — отступ блока от верхнего края. Блок прижат к верху, а не центрирован: отступ равен интервалу между группами минус 20px.
- `--tracking`, `--leading` — трекинг, интерлиньяж.
- `--key`, `--gutter`, `--value` — ширина колонки ключей, отступ и длина самого длинного значения, в знаках. Сетка общая для метаданных и футера, поэтому значения стоят на одной вертикали.
- `--size` — кегль: 15px → 22px. На узких экранах он сам уменьшается (до 12px) ровно настолько, чтобы самая длинная строка (email, 24 знака) не переносилась: около 13.4px на 360px, 15px начиная примерно с 400px. Если самое длинное значение изменится — поправить `--value`.
- Между двумя ссылками футера на телефонах есть небольшой зазор (`footer .pairs { row-gap }`), чтобы расстояние между строками было не меньше 24px — это требование к touch-целям, без него Lighthouse Accessibility падает до 91. На десктопе зазор равен нулю.

## После правок в `styles.css`

GitHub Pages разрешает браузерам кэшировать файлы на 10 минут, и телефоны часто показывают старые стили. Поэтому при каждом изменении `styles.css` нужно увеличить номер версии в ссылке на него: `styles.css?v=2` → `?v=3` в `index.html` и `cv/index.html`.

## Перерендер `og-image.png`

Поднять локальный сервер (см. выше) и снять скриншот `og-image.html` в headless Chrome:

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --hide-scrollbars --force-device-scale-factor=1 --window-size=1200,630 --virtual-time-budget=8000 --screenshot="$PWD/og-image.png" http://localhost:8766/og-image.html
```

Если процесс не завершился сам после появления файла — остановить через `Ctrl+C`, картинка уже записана.

## Деплой на GitHub Pages

1. **Репозиторий.** Создать публичный репозиторий на GitHub и запушить в ветку `main` все файлы из этой папки (в корень репозитория).

2. **Pages.** В репозитории: Settings → Pages → Build and deployment → Source: **Deploy from a branch** → Branch: **main**, папка **/ (root)** → Save.

3. **DNS в Namecheap.** Domain List → Manage → Advanced DNS. Удалить парковочные записи по умолчанию и добавить:

   | Type | Host | Value |
   | --- | --- | --- |
   | A Record | `@` | `185.199.108.153` |
   | A Record | `@` | `185.199.109.153` |
   | A Record | `@` | `185.199.110.153` |
   | A Record | `@` | `185.199.111.153` |
   | CNAME Record | `www` | `lipnitskyigor.github.io` |

   IP-адреса GitHub Pages иногда меняются — перед настройкой сверить с актуальной документацией:
   <https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site>

4. **Домен и HTTPS.** Settings → Pages → Custom domain: `lipnitski.com` → Save. Дождаться, пока пройдёт DNS check (от нескольких минут до суток), затем включить **Enforce HTTPS**. Файл `CNAME` в корне уже содержит домен — если GitHub перезапишет его коммитом, это нормально.

5. **Обновить CV.** Заменить `cv.pdf` в корне на новый файл с тем же именем, закоммитить и запушить. Адреса `lipnitski.com/cv` и `lipnitski.com/cv.pdf` продолжат работать.
